## 适用范围与开启方式

新增`ctflab_recoverable_log.py`，仅为Darwin/Linux通用驱动的新启动提供可选日志链。在新实例的可信运行时配置中显式设置`"recoverable_logs": true`，按既有配置导入/准备/启动流程使用；布尔值严格核对，Windows显式请求时在实例创建前拒绝，缺失/false保持原链。已发布Mac App不含此源码，新功能不自动修改已有配置或旧启动尝试。

每次新启动在自己的`runtime/00000001`等尝试目录创建私有`log-channel/stderr.fifo`。固定启动清单记录实例/代次/节点/尝试，通道再绑定启动清单摘要及FIFO的设备/inode。生产者只获得对应FD作为stderr，不获得任意路径/远程命令。接收器独立于启动管理进程，每次使用新UUID片段目录；不监听网络、不修改宿主路由、系统服务或信任根。

生产者FD以读写方式打开FIFO，因此接收器退出时仍保留内核队列。Linux文档明确这种行为，POSIX本身没有统一保证；本机Darwin已用自有进程实际核验，不据此宣称所有POSIX/文件系统都支持。参考[Linux FIFO说明](https://man7.org/linux/man-pages/man7/fifo.7.html)与[Apple open说明](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/open.2.html)。

**接收器失效后，队列写满会使生产者等待，并可能阻塞QMP。** 这是保留有限内核队列的背压，不是不中断服务保证。显式重接后可继续排空；不会自动重试、安装守护服务、重新启动或停止生产者。持锁接收器若仍存在但挂起，本入口拒绝再开第二读者；没有强杀/强行释放锁入口。

## 并发、身份及证据保留

- `receiver.lock`由内核排他锁覆盖整个接收过程；目录门和原驱动命令门分别保护请求与生命周期。先有新片段意图，再派生固定接收程序。ready还须绑定通道摘要、真实自有Popen PID/创建身份；未收到就绪回执不启动生产者，保留未知意图和部分材料。
- 同一个恢复操作标识再次调用只查原意图，不再次启动。先前请求未知时不能换标识盲目重发；应重新读取源进程和接收锁状态。尝试最多16个日志会话（含首次），达到上限拒绝且保留全部片段。
- 所有片段日志合计最多8MiB；新接收器按旧片段实际长度计算剩余预算。预算为零时继续排空、不再写载荷。旧片段不覆盖、截断或删除，部分状态文件也保留。独立文件/硬链接/符号链接、FIFO身份和启动清单变化均保守拒绝。
- 某次接收器崩溃时，已经从内核读取但尚未写盘的数据可能丢失，计数也可能未提交；恢复不推断完整性，`capture_complete=false`。新片段保存随后读到的字节，不补写、重放生产者输出或把新日志伪装成旧片段。
- EOF只说明FIFO写端关闭，不能证明生产者退出、文件系统干净或正常关机，`process_exit_verified=false`。源进程退出证明仍走原独立退出观测链。
- 本功能只替换显式选择的新QEMU stderr通道；旧匿名日志管道、worker/桌面控制台、Windows管道不被接管。宿主重启后旧FD/内核队列不会恢复，也不能通过重开FIFO制造同一队列。

## 驱动及两端入口

通用驱动`rearm-log`先在原代次/节点/尝试下核对启动清单、磁盘及进程身份，再按原实例/代次/状态revision门处理新日志接收请求。它不发送QMP命令，不依赖可能被背压堵塞的QMP查询，也不解除其他生命周期或来宾动作的原门禁。

React与原SwiftUI通用场景展示接收锁、历史可能缺口及“重接日志接收器”。源进程身份必须已通过原生核验、通道匹配、接收锁可用、契约没有活动操作、状态版本及窗口有效。仅此日志恢复允许“一致但逐节点查询不完整”的窗口；跨代次/采样中变化/过期、后台执行中、错节点、旧匿名管道和未知源身份均禁止。生命周期/容器/服务按钮仍要求完整采样，不因日志恢复放宽。

UI请求绑定原根、实例、代次、revision、节点与新的attempt_id。后台再次核验，前端允许不等于已接收成功；丢回复只读刷新，不自动重发。Mac固定根stdin白名单同步接入，不新增任意路径、shell或外部目标。

CLI只用于明确选定的已配置通用实例，不代表本文已执行用户环境操作：

```text
python3 -I -B tools/ctflab_qemu_driver.py supervision --run /explicit/private/instance --node server
python3 -I -B tools/ctflab_qemu_driver.py rearm-log --run /explicit/private/instance --node server --operation-id <明确的UUID>
```

旧实例/启动没有已登记FIFO时拒绝；不要为了启用本功能修改活动配置或重启现有VM。本轮没有在任何用户实例中开启该选项。
