# CTFLab 产品与跨平台方案评审

> 2026-10-21。结论：值得继续，但应先完成 Windows 教学工具的最小闭环，再扩展平台能力。现有方案可作为方向和任务库，尚不适合作为整个平台的确定排期。第1—6节保留初次评审基线；本次规划修订的采纳情况见第7节，不代表功能已实现或通过实机验收。

评审对象：[产品规划](ctflab-product-roadmap-2026-10-15.md)、[Windows 专项](ctflab-windows-plan-2026-10-15.md)、[任务表](ctflab-implementation-backlog-2026-10-15.md)，包括 10 月 21 日确认的 E01→E02→E03 顺序。评价依据为教学与个人练习优先、Windows x64 为下一重点。

评审后目标补充：用户进一步提出供社区使用。总规划第1.1节和任务表 U01—U04 已记录这一需求；本报告中的39项为补充前的评审基线，当前任务表为43项。随后用户要求统一 Windows 社区预览范围与门槛，第7节记录本次文档处理；社区自助安装、诊断、内容贡献和维护已纳入 G1 规划，不表示已完成产品验收。

## 1. 总体判断

**做成稳定的教学实验工具，值得投入；一次实现参考图里的全部平台能力，范围过大。** 最直接的价值是：老师能够交付可复现的实验，学生能够进入、完成、保存和恢复它，出问题时可以定位原因。拓扑、Docker、远程运行和流量分析应围绕这个使用过程逐项加入。

| 评价方面 | 结论 | 依据与限制 |
| --- | --- | --- |
| 教学定位 | 清楚，符合已确认需求 | Windows 单机、内网多机、应急分析可共用实验与证据管理；尚无学生试点数据 |
| 架构方向 | 可继续验证，无需整体推翻 | 保留 Python 核心、分离平台适配、先通用场景再编辑器，可以沿现有代码逐步推进 |
| 首轮交付 | 需要收缩和明确门槛 | Windows 显示/控制/运行时仍是候选，最终包门槛与任务编号不完全对应 |
| 维护成本 | 全量展开会明显增加负担 | 当前 39 项任务涉及多个宿主、两套界面、VM/容器、内容分发、远程与课程 |
| 商业判断 | 现阶段不能下结论 | 没有采购意向、持续使用或维护成本数据；技术方案完整不等于市场需求已验证 |

可形成产品特点的是“课程配方 + 可靠恢复 + 明确隔离范围 + 可追溯证据 + 外部 VM 接入”。是否比用户现有做法更省时间，需要实际课堂比较。本轮没有调查竞品功能、价格或市场规模。

## 2. 应保留的设计

- Windows 宿主与 Windows/AD 课程分别验收，避免把运行器打开误当成课程可用。
- 原盘只读、派生磁盘、实例代次与身份核验，保障学生重做实验和故障恢复。
- 先通用场景契约，再做拓扑编辑。当前校验仍限定 Wintermute，不能让界面能力先于执行能力。
- Docker 先置于受管 Linux VM，远程先让整个场景在一台执行机运行，限制初期网络与恢复组合；资源和隔离效果仍需实测。
- 外部 VM 初期保留原软件的生命周期管理，按 E01 Kali→E02 Windows→E03 域环境增量推进；跨运行器恢复不能只重置一边。
- 应急原证据、调查副本和处置副本分开，教师真值单独分发。C05 可先产生教学价值，无需等待云端平台。

## 3. 评审发现与关闭条件

以下“高”表示在对应阶段验收前必须关闭，不表示已发现已发布 App 的故障，也不要求第一轮实现全部后续能力。

### R1｜高：G1 门槛在文档间没有唯一对应关系

**位置：** Windows 专项第 6 节 W0—W5、任务表 W01—W06、总规划第 11 节 G1。

专项写“G1 只需要 W0—W3 与 C01”，这里 W3 是 GUI；任务表 W05 才是安装包、离线依赖和更新，W06 才是设备与课堂试点。总规划又要求干净机器上的最终安装包。编号易混，按专项执行可能将 GUI 完成误当成 G1 完成。

**建议与关闭条件：** G1 统一引用任务表 ID，明确 A01—A03、W01—W06 的首版适用范围及 C01；专项阶段改成不与任务 ID 相似的名称。封闭原型、课堂预览、正式分发分别声明签名和设备覆盖条件。门槛必须能唯一定位包、设备、课程及失败恢复记录；缺失 Intel/AMD 样本时缩小支持声明，不能笼统写两者均支持。

### R2｜高：Windows 运行时与显示候选尚未形成可交付组合

**位置：** Windows 专项第 3.3 节、W01/W03/W04、总规划第 4.2 节。

计划已正确把受保护 QMP 和显示列为原型风险；后续界面、打包和预算仍建立在原型能顺利通过的假设上。Windows SPICE 客户端或来宾驱动可下载，不足以证明本项目所需的 Windows QEMU 服务端、TLS、固件和重连组合可交付。官方分别列出客户端、来宾组件和服务端，需要逐层核验。[SPICE 组件说明](https://www.spice-space.org/download.html)

**建议与关闭条件：** W01 先交付锁定版本和构建来源的最小运行时，实测 WHPX、受保护控制、显示重连、正常停止、监督异常恢复和 socket 交接，再投入完整 GUI。显示以输入、缩放、重连与访问控制验收；若 SPICE 不达标，可评估受保护 VNC 等候选，但须修订设计和独立验收。

关闭证据是一台获准 Windows 实机的完整探针记录、依赖清单与构建配方，以及候选取舍。本轮没有证明 Windows SPICE 构建不可用，也没有实测任何候选可用。

### R3｜高：缺少同一 Windows 宿主同时运行两套虚拟化软件的门槛

**位置：** Windows 专项第 7 节、总规划第 9.3 节、E01—E03。

现有矩阵覆盖 VPN、路由和端口，但未明确 QEMU/WHPX 与 VMware Workstation 或 VirtualBox 同时运行的组合。网络配置正确，不能单独证明这种部署可用。

Broadcom 记录了部分 Windows 11/Workstation 组合在 VBS 启用后的性能问题；Oracle 的 VirtualBox 7.2 故障说明也列出与 Hyper-V 同宿主的冲突/性能情形。资料支持“必须测具体组合”，不支持“全部不能共存”或“全部稳定共存”。[Broadcom 说明](https://knowledge.broadcom.com/external/article/417896/after-the-host-os-upgrade-to-version-win.html)、[Oracle 说明](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/Troubleshooting.html)

**建议与关闭条件：** W01 做轻量兼容探针，E01 做课程验收。分别测 QEMU + Workstation、QEMU + VirtualBox，不要求首版同时运行三个引擎。记录 Windows 构建、CPU、WHP/Hyper-V/VBS 状态、软件版本、单独/同时运行表现、课堂响应及睡眠恢复；先支持一个通过的组合。

同宿主与异宿主分别公布支持范围。关闭 WHP 不能作为 QEMU/WHPX 共存修复，也不默认要求关闭宿主安全功能；不达标时评估独立执行机路线。

### R4｜高：外部 VM 的隔离承诺超出了计划中的管理权限

**位置：** 总规划第 9.3 节的外部生命周期、隧道、宿主/LAN 禁通要求。

CTFLab 初期只管理实验接入路径。用户管理的外部 Kali 若另有 NAT/桥接网卡，或其管理员改变转发规则，限制隧道 CIDR 不能证明该 VM 没有其他出口，也不能阻止它通过允许的应用连接转发数据。这是基于管理边界的设计判断，本轮没有做隔离突破测试。

**建议与关闭条件：** 区分“CTFLab 网关所控制路径的隔离”和“外部 VM 所有路径的隔离”。登记外部 VM 标识、网卡、路由、允许服务，限定对等端地址和网关规则。额外出口无法核验时，不显示全场景隔离已验证。要求完全封闭的课程选择所有接口均受控的模板；不能仅依赖来宾内检查脚本证明强隔离。

验收覆盖接入前后、身份变化、额外网卡、路由变化和断线的允许/拒绝矩阵。产品应分别显示连接状态与隔离验证状态，说明外部配置无法核验的范围。

### R5｜高，限 C04/E03：域恢复需要覆盖无健康复制伙伴的样板

**位置：** 总规划第 10.1 节单域样板与全场景重置、C04/E03。

方案已要求 VMGenID、DNS、时间、机器信任和整体恢复，方向正确。但首个样板可能只有一台 DC，或全部 DC 同时恢复。微软说明中的安全恢复包括从复制伙伴进行目录与 SYSVOL 非权威同步，不能直接把存在健康伙伴的机制当成所有教学拓扑的恢复证明。[Microsoft 虚拟域控恢复架构](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/get-started/virtual-dc/virtualized-domain-controller-architecture)

**建议与关闭条件：** 单 DC、全域冷基线恢复单列样本，验证 SYSVOL/NETLOGON、DNS、时间、机器账户安全通道、新发起的域认证与课程业务。已有会话不算恢复后重新认证成功。区分新建、复制和恢复的标识规则，不靠固定 VMGenID 绕过恢复保护。

需要选定 Windows Server/QEMU/固件版本、全套状态恢复规则和连续恢复业务记录；失败保留现场。此项阻止 C04/E03 宣称可用，不阻止先交付 Windows 主机运行器或单机课程。

### R6｜中：部分依赖把基础保护或独立价值放得过晚

**位置：** 任务表 T02、P03、C02、O01、E01。

| 现有安排 | 影响 | 建议调整，尚未采纳 |
| --- | --- | --- |
| T02 依赖 T01/S02，未显式依赖 S03 | 可编辑草稿与可执行新场景容易混在一起 | 草稿可先做；发布可执行模板必须经过 S03 与实际场景验收 |
| P03 依赖在线内容 P02；O01 又依赖 P03 | 本地空间预检、证据保留被在线分发拖后 | 拆成本地存储/保留和在线缓存回收，前者随本地生命周期推进 |
| C02 依赖 Windows 宿主 CLI W03 | 来宾配方准备不必要地绑定宿主移植 | 在另行获准的 x64 环境准备来宾基线；CTFLab 各运行器仍分别验收 |
| E01 在 P3/G4，与远程同阶段 | 用户已有 Kali 的接入价值可能等到 Docker/远程后才出现 | Windows 主线与 E01→E02→E03 顺序保留；S03/S04 到位后可按课程需求提前 E01 |

**关闭条件：** 统一任务依赖图与 G1/G2/G4，区分“可先准备”“可执行”“可发布”。本次未擅自改变既定优先级。

### R7｜中：全量能力的维护成本尚未进入投入模型

**位置：** 总规划第 4.2、11、12 节与 39 项任务整体范围。

两套界面、三个宿主方向、VM/容器、外部虚拟化组合、远程协议和课程，会产生持续兼容测试与更新成本。原稿已将 G0 的 1—2 人周、G1 追加 3—6 人周标为初始估算，但尚无 Windows 原型、构建链和实机维护数据支撑，不能据此承诺日期。

**建议与关闭条件：** G0 后按剩余工作重估；固定首版支持矩阵、设备与维护责任。共享命令/事件协议和验收用例，避免两套 GUI 各自发展业务规则。每增加一种宿主、引擎或课程，明确新增测试成本和旧组合淘汰规则；开发、课程制作、设备/签名、用户支持分别记录。

## 4. 建议先交付的产品

学生打开 Windows 版，导入老师的离线课程，软件检查设备与空间，说明不能启动的原因；启动 Kali 与一台 Linux 靶机，打开控制台/服务入口并显示真实状态。学生能保存进度、正常停止、恢复课程初态、导出故障信息。老师有完整任务、答案和复现说明。这个范围完成后，就可开展真实课堂试点。

以下顺序是评审建议，下一次修订时再与任务表统一，不替换已确认的 Windows 优先与 E01→E02→E03 顺序。

1. **Windows 技术闭环：** A01/A02、必要 A03、W01；只做验证平台路径所需的最小界面或驱动。
2. **Windows 教学预览：** W02—W06 + C01；另准备可独立交付的 C05 应急证据课，最终包与学生使用分别留证。
3. **通用多机与课程：** S01—S04、只读拓扑、C02/C03；按课程需要选择 E01 与模板编辑先后。
4. **按瓶颈扩展：** Web 课程复用需求强则推进 Docker；学生电脑带不动实验则推进 Linux 单节点远程。C04/C06 通过域恢复/现场封存验收后进入课堂。
5. **持续需求明确再建设：** 自由拓扑、跨站点网络、多人平台、WAF/态势展示、分布式镜像服务。

随后让 Windows 单机、双网段内网、应急证据分析各有一个完整样板。三者可共用运行器，但必须分别证明能完成教学任务，不能以节点全绿代替。

## 5. 怎样判断产品是否好用

| 使用结果 | 建议验证 | 用于决定 |
| --- | --- | --- |
| 学生进入实验顺利 | 5—10 名未参与开发者使用最终包，逐人记录安装、导入、进入课程与人工介入原因 | 先修可用性还是增加功能 |
| 节省课堂准备时间 | 同一课程对比原有流程与 CTFLab；下载耗时分开记录 | 工具价值是否成立 |
| 课程可重复 | 建议连续 3 轮完整停止/重置/重做，核对原盘、业务、网络和资源释放 | 是否足以稳定上课 |
| 错误能恢复 | 磁盘不足、进度取消、GUI 退出、端口冲突和监督异常 | 教师处理环境问题的负担 |
| 设备体验可接受 | 固定内容与版本，按支持组合记录耗时、峰值内存、磁盘增长和一节课运行表现 | 支持范围及是否提前远程路线 |
| 教师愿意再次使用 | 第二次课程继续使用，记录维护量、内容修改与问题 | 是否值得持续扩展 |

原规划“内容已到本地后 15 分钟内进入 C01”可保留为目标。上述人数、轮数和指标是建议，不是已取得结果。小样本公开逐次结果和设备差异，一次演示不能证明商业市场。
