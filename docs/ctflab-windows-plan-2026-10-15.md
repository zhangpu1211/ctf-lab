## 1. 支持目标与边界

第一版目标为处于支持期的 Windows 11 x64、开启硬件虚拟化，使用受控 QEMU x86_64 + WHPX。Intel/AMD 是候选覆盖范围；首版只声明已通过的具体 Windows 构建、CPU、显卡与驱动组合，可以先覆盖其中一个 CPU 家族。设备数量与发布条件统一见第 6 节，不声称任何 Windows 电脑均兼容。

Windows 10、Windows ARM64、Windows Server 宿主、嵌套虚拟化、WSL2 运行 CTFLab、GPU 直通均不作为首版发布门槛。QEMU 当前官方 WHPX 文档也描述 ARM64 支持，但不能因此宣称 CTFLab 已支持 Windows ARM；本项目先控制 x64 范围。[QEMU WHPX](https://www.qemu.org/docs/master/system/whpx.html)

必须分开四个维度：

| 维度 | 示例 | 不可混淆的结论 |
| --- | --- | --- |
| 宿主 OS | macOS / Windows / Linux | 决定进程、路径、权限和加速接口 |
| 宿主架构 | arm64 / x64 | 决定可直接硬件虚拟化的来宾架构 |
| 客体 OS | Kali / Windows Server / Windows 客户端 | 决定驱动、服务、授权和课程验收 |
| 客体架构 | aarch64 / x86_64 | 不能通过 QCOW2 格式转换改变 |

### 1.1 加速与内容选择

| 宿主 | 来宾 | 默认策略 | 教学含义 |
| --- | --- | --- | --- |
| Mac ARM64 | Linux ARM64 | HVF，保持现有受控路径 | 日常 Kali / 原生 ARM 工具节点 |
| Mac ARM64 | Linux/Windows x64 | 显式 TCG 兼容模式 | 逐场景测量，重型域实验推荐 x64 执行节点 |

加速器不可用时先解释原因；需要硬件加速的课程直接拒绝，允许模拟的课程须由用户选择后再运行。禁止静默降级后仍宣称正常性能。`-accel help` 只能证明构建包含后端，不能证明当前机器能成功执行来宾。[QEMU 系统说明](https://www.qemu.org/docs/master/system/introduction.html)

## 3. 推荐技术路径

原生 Windows QEMU + WHPX，不把 WSL2 或 Docker Desktop 作为基础依赖。学生不需要安装 Python、pip、Node 或编译工具。运行时打包 QEMU、qemu-img、Python、固件及必要显示组件，版本与哈希固定并附组件来源/许可。

首轮先实现 CLI 与内部调用，第二轮接桌面界面。Tauri 2 负责窗口、受限 IPC 与 Windows 安装包；Python 内核负责业务；React/TypeScript 负责界面，React Flow 用于后续拓扑。需核验 WebView2 并提供离线安装途径，不能只打包一个需要联网下载的引导器。[Tauri sidecar](https://v2.tauri.app/develop/sidecar/)、[Windows 安装与 WebView2](https://v2.tauri.app/distribute/windows-installer/)

### 3.1 进程与恢复

`ProcessSupervisor` 应保存实例 UUID、代次、进程创建时间、可执行文件身份、角色和命令摘要；Windows 使用进程句柄与创建时间等原生信息，命令摘要还需结合实际端点和启动记录核验，不能只读取本地 JSON 自证身份。PID 匹配不充分；读权限不足归类为 unknown，拒绝破坏性操作。

采用后台监督进程管理 QEMU、网络服务和显示客户端，GUI 关闭不等于退出监督进程。Job Objects 可用于绑定子进程组、资源控制和退出通知；**不能把 GUI 的 Job 配置为关窗即强制终止所有 VM**。是否使用 `KILL_ON_JOB_CLOSE` 须按角色分别设计：短时转换任务可清理，承载实验的 VM 需满足失败保留与可接管要求。[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

正常停止顺序：发出 QMP ACPI 关机 → 等待来宾与进程 → 核验已停止 → 释放资源。超时保留状态，明确提示来宾可能等待确认；强制结束是单独操作。GUI 崩溃、监督进程崩溃、宿主重启分别测试；恢复时重查句柄/身份/端点/磁盘绑定，不能按旧 PID 直接终止。

### 3.2 锁、路径和存储

- `StateLock` 采用 Windows 原生排他文件锁候选（如 `LockFileEx`）并包装成与 POSIX 相同的接口；锁文件存在不代表锁仍被持有。跨进程竞争、异常退出释放、继承句柄和重复打开行为必须真实验证。[Microsoft LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)
- 私有运行状态默认位于 `%LOCALAPPDATA%\CTFLab`，软件目录只读；镜像库可由用户另选，不能把个人凭据写入可分发目录。
- 用 ACL 表达仅当前用户等可信主体可访问，不能把 `chmod 0700` 当成 Windows 已实现同等保护。检查 junction、符号链接和其他 reparse point，防止状态路径越界。
- 全程使用参数数组，避免 `cmd.exe /c` 拼接。测试中文、空格、括号、不同盘符、大小写归一、长路径和保留文件名；不能把路径一律小写后用来计算身份。
- 第一版活动状态只支持已验证本地文件系统；网络共享、同步盘、可拔移动盘作为来源导入可以评估，直接作为活动 overlay 默认不支持。
- 不依赖 APFS clonefile、硬链接或 POSIX 原子 rename 的特性。Windows 文件被打开/扫描时替换失败，保留旧文件和操作日志；有限重试后给出明确恢复步骤。
- 重置先准备新代次全部磁盘/NVRAM/配置，验证后切换活动指针；持久化顺序、崩溃后恢复、跨卷行为分别验证。禁用跨卷“原子提交”假设。

### 3.3 QMP 与显示控制通道

Windows QMP 选择是 G0 阻断项，不能先使用无保护 TCP 应付。原型按以下顺序核验：

1. 候选 QEMU 构建是否支持可重连的本地命名管道后端，以及能否正确控制 ACL、句柄生命周期和客户端身份。
2. 若原生管道不可用，采用回环 TCP + 双向 TLS 身份验证/授权策略，证书与私钥仅监督进程可访问；同时确认该 QEMU 构建具有对应 TLS 支持。
3. 如果两者均不能满足恢复和访问控制，只开放受监督的开发原型，不发布声称可恢复的 Windows 产品；重新选择运行时构建或传输方案。

通过匿名 stdio 控制 QMP 可用于短时探针，但没有独立持久监督与重连方案时，不作为正式运行中的唯一控制链路。QEMU 官方将 monitor 视为高权限接口，并要求 TCP 传输同时具有 TLS 与授权控制。[QEMU monitor 安全说明](https://www.qemu.org/docs/master/system/security.html)

显示首选经过验证的 Windows SPICE 服务端/客户端配套；同时验证中文输入、缩放、DPI、焦点切换、独立重连和剪贴板默认关闭。不能将 macOS 定制 spicy 二进制直接复用到 Windows。

W01 必须锁定 QEMU 服务端、显示客户端、TLS/访问控制组件和固件的具体版本、构建来源、配方与哈希，并形成完整探针记录；仅客户端可下载或二进制可启动不足以选型。如果 SPICE 未达标，可评估受保护 VNC 等替代候选，先修订显示设计并独立通过同等输入、缩放、重连和访问控制验收，再进入完整 GUI。CLI/SDL 只能作为明确标注限制的封闭技术原型，不满足 G1；公开交付另需授权。Windows 来宾 RDP 是实验服务，不等同于运行器通用显示后端。

### 3.4 网络与端口交接

保留回环用户态二层交换机，首版不安装 TAP 驱动、不桥接物理网卡。每个实例独立网络服务、租约和账本。普通应用权限运行，确需启用 Windows 功能等宿主变更时单独提示用户处理，不要求长期管理员运行。

当前 `pass_fds` 是 POSIX 行为，不能在 Windows 上原样调用。原型优先验证 Python socket sharing/Windows socket duplicate 的受控交接；若由子服务自行绑定，则它必须一次性绑定并持续持有端口，通过私有 IPC 提交真实端点和身份，父进程校验后登记，最后才启动 QEMU。禁止“检测端口空闲→关闭→稍后再监听”的竞态模式。

网络就绪不能只检查“端口能连接”；应校验本次会话身份、配置摘要和归属。Windows 防火墙权限、重启后的策略和不同用户账户需要真实测试，不默认添加允许所有网络的入站规则。

路由读取优先 Windows IP Helper API 或固定受控命令的结构化输出；覆盖 VPN/TUN、默认路由、具体实验 CIDR、双栈和采集失败。任何宽松规则变更须有针对性证据，不能为了适配 Windows 绕过现有路由冲突保护。

回环 TCP 限制外部网络暴露，但不能证明同一宿主上所有本地进程均不可信时仍隔离。第一版定位单用户教学；多人执行节点需额外用户/进程/网络隔离后再开放。

## 4. Windows 来宾、域环境与应急课程

这是与宿主适配独立的工作包，Windows 来宾也可以在后续 Linux x64 KVM 上运行。

1. **单机基线**：授权安装介质、受控安装配方、q35/固件/磁盘和网卡驱动的实测组合、补丁清单、控制台与必要服务、关机/重启/恢复。
2. **来宾系统要求**：按选定 Windows 版本验证 Secure Boot、vTPM、CPU 等要求；不将 Server 与桌面版要求混为一谈。vTPM 与 NVRAM/磁盘同代次保护，密钥不入内容索引。
3. **域环境**：DNS/DC、成员机、Kali 等角色先定义稳定地址与启动依赖；采用封闭实验域，不联入真实组织域。健康检查覆盖时间偏差、DNS 解析、域登录与预期服务。
4. **域控恢复**：QEMU VMGenID 设备与 AD 来宾配套验证；创建、复制、快照恢复时的标识变化规则单独测试，不以固定 VMGenID 绕过保护。单 DC 和全部 DC 从冷基线恢复须分别覆盖无健康复制伙伴的情况，检查 SYSVOL/NETLOGON、DNS、时间、机器账户安全通道、新发起的域认证与课程业务；已有会话不能代替重新认证。全场景一致恢复需覆盖机器账户、域状态、日志和时间服务，失败保留现场。此项属于 C04/E03，不阻止仅交付 C01 的 G1。[QEMU VMGenID](https://www.qemu.org/docs/master/specs/vmgenid.html)、[Microsoft AD 虚拟化恢复](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/get-started/virtual-dc/virtualized-domain-controller-architecture)
5. **应急现场**：通过预制日志或受控事件构造教学初态；证据导出到独立只读保留区，执行清理/恢复前要求完成现场封存。Windows 事件日志/Sysmon 等来源须记录配置与覆盖范围。
6. **分发许可**：Windows 介质、驱动、工具的再分发权分别核验；优先分发配方并由用户提供介质。官方评估版本有使用条件和期限，不在工具中绕过激活或延长限制。[Microsoft 评估入口](https://www.microsoft.com/en-us/evalcenter/download-windows-server-2025)

内存规划先用实测样板确定。可先准备 16 GB 主机做小型 Linux/单 Windows 组合试点，32 GB 或以上做基础域场景评估；这只是测试机采购/借用的初始档位建议，不是已证明的最低配置。还需测量 CPU 架构、磁盘空间/IO、后台应用和节点峰值。

## 5. Windows 打包和发布

- 在原生 Windows 构建环境生成发布包，固定 QEMU/Python/固件/显示组件/GUI 版本、哈希、编译配方、许可证和 SBOM；交叉编译产物必须回到 Windows 验收。
- 应用安装与用户数据分离；按用户安装为默认候选。卸载软件保留镜像库、进度和证据，删除数据另行明确选择。
- 提供联网安装包和课堂离线依赖包；离线环境可安装 WebView2、导入已下载内容并完成实验，不要求实时登录云账号。
- 启动前检查 WHP 功能、固件虚拟化和实际 WHPX 探针。WHP 未开启需要系统设置和可能重启，不静默启用或改变其他虚拟化软件配置。[WHPX 前提](https://www.qemu.org/docs/master/system/whpx.html)
- 面向不特定用户公开的 G1 社区预览及后续正式分发，均要求最终安装包/自有可执行文件的 Authenticode 签名验证通过，随包第三方组件记录来源、哈希与签名状态；证书/签名服务单独配置。签名缺失时只能留在有明确参与者和风险说明的封闭试点，不能将其标为 G1 通过。签名不保证消除所有 SmartScreen 或企业策略提示，记录干净设备实际结果。[Tauri Windows 签名](https://v2.tauri.app/distribute/sign/windows/)
- 更新先校验签名与完整性，再准备新版本；运行实例期间延迟替换其运行时。旧运行时保留到没有实例引用；状态迁移失败恢复旧版本和旧数据，不能只回滚 EXE。
- 各发布渠道绑定构建提交和最终 ZIP/安装包哈希，测试来自解压后的最终资产，覆盖遗漏 Python 模块、固件、显示 DLL 等情况。

## 6. Windows 社区预览范围与统一验收门槛

本节为总规划 G0/G1、任务表及 U01—U04 的唯一门槛入口；原 W0—W5 切片编号撤销，下面使用描述性阶段名与任务表 ID。所有结果当前均为待实现/待验证。G1 指 **Windows 社区预览**，不代表稳定正式版；封闭课堂试点是进入 G1 的验证活动，不能以试点包代替社区最终包。

### 6.1 首版范围与阶段

首版限单用户本地运行、已验收 Windows 11 x64/WHPX 组合、一个固定版本的离线 C01（Kali x64 + 一台 Linux/Web 靶机）。包括环境/空间预检、导入、控制台和服务入口、保存进度、停止后继续、整课重置、失败恢复和本地脱敏诊断。保存进度以持久运行盘及正常停止后继续为界，不承诺内存快照跨版本迁移。

C01 是受限的双节点课程配方：W03/W04 必须提供两节点的资源归属、统一停止/重置与失败保留，不能复用 Wintermute 固定三节点契约并假称已有通用引擎。可先分别准备单节点资产；课程验收必须证明组合闭环。若实现只能依赖通用场景路径，则把必要 S01/S03 切片显式纳入 G1 并更新依赖，不能因本节不要求完整 v2 而省略安全语义。

| 基础策略准备 | A01/A02；A03 本地命令/事件契约 | Mac 等价与错误组合验证；远程协议实现后置 |

### 6.3 后续能力的独立门槛

- **R3 / E01—E03 共存**：W01 登记 Windows 构建、CPU、WHP/Hyper-V/VBS 与虚拟化软件版本，做获准组合的轻量兼容探针；没有设备可标未测。QEMU + Workstation、QEMU + VirtualBox 分别验证单独/同时运行、课堂响应和睡眠恢复，先支持一个通过组合，不要求三引擎同时运行。完整同宿主课程验收归 E01；G1 可以只支持 CTFLab 单独运行且明确共存未验收，不能宣传外部接入。异宿主另列矩阵；不默认关闭宿主安全功能或以关闭 WHP 冒称 WHPX 共存修复。
- **R4 / E01—E03 隔离**：分别显示连接状态与隔离验证状态。只对可控制且实测的网关路径作承诺；登记外部 VM 身份、网卡、路由、对等端和服务，覆盖额外网卡、身份/路由变化及断线。外部其他出口无法核验时不得标全场景隔离通过；完全封闭课程须使用所有接口受控的模板，来宾检查脚本不能单独证明强隔离。
- **R5 / C04/E03 恢复**：以第 4 节无健康复制伙伴的样本与完整业务复验为门槛；选定 Server/QEMU/固件与全套状态恢复规则，连续恢复记录须含新认证。跨运行器还需外部恢复点和内部代次一致。缺证据阻断域课程，不阻断 C01。
- **R7 / 投入**：G0 后分别记录开发、课程制作、设备/签名、支持维护成本，再估剩余工作；不以初始人周承诺日期。每新增宿主、引擎或课程均指定维护责任、增加验收矩阵与退出规则，共享协议和用例，避免两套 GUI 发展不同业务语义。

## 8. 决策门与备用路线

- WHPX 对指定旧靶机不兼容：保留其原硬件配置作为候选，单独尝试已声明的 TCG 兼容运行；不修改漏洞、账号或课程内容来伪造通过。
- SPICE 不满足输入/恢复：先修复受控客户端或缩小预览范围；不为了赶版本宣传完整桌面体验。
- Windows QMP 保护或恢复未通过：阻止 G1 发布，不以无鉴权 TCP 降低门槛。
- 学生设备不足：让同一前端连接已授权的 Linux x64 执行节点，先把整个场景移过去，不做单个节点的临时跨云拼接。
- 新 UI 成本超出预期：先完成 CLI 和运行协议，保留 Mac GUI；通过原型结果再决定桌面壳，不开展三套独立业务逻辑。

本文件中的命名管道、socket sharing、Windows SPICE 与 AD 恢复均是必须验证的候选路径；本轮没有实际证明它们可用于 CTFLab 当前运行时构建。
