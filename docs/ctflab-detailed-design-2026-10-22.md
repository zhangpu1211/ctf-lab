# CTFLab 全路线图详细设计基线

日期：2026-10-22。范围：既有43项任务；本文件完成设计分解，不表示实现或实机验收完成。优先级及原始完成标准继承实施任务表；新增要求与旧要求同时满足。Windows由用户执行实机验证，现有Mac发布包保持独立。

## 1. 入口、数据与责任

现场代码依据：主CLI提前分派 local-contract、scenario-plan-v2、course-catalog；LocalAdapter取得可信进程主体后调用LocalService；LocalService持久化请求、实例、事件，通过注入后端执行；scenario_v2.instance_plan生成排序、资源名和计划摘要；catalog负责精确变体与只读资产校验。现有Wintermute执行链继续服务v1，v2不得直接复用其三节点特例并声称通用执行完成。

目标调用链：桌面/CLI → 本机认证适配器 → LocalService → 场景协调器 → 宿主监督器/存储/网络/显示适配器。UI不直接启动QEMU、不拼宿主命令、不改数据库。内容只提供严格声明；可执行文件和参数由受信运行时构造。

共同标识：actor、instance_uuid、generation、revision、operation_id、幂等键、plan_sha256、资产摘要和runtime_manifest_sha256。请求相同键且不同内容拒绝；代次或revision过期拒绝；重复请求返回已记录结果。事件按实例递增，断档返回全量快照和新的游标，不根据旧事件重放副作用。现有协议不兼容的字段进入新版本，先协商再执行，不静默接受未知字段。

运行证据单独保存：检查ID、对象/代次、观测时间、观察器版本、通过/失败/未测/不适用、证据引用。process-running、guest-ready、service-ready、course-verified分别由对应观察产生；历史结果和内容声明不能升级当前实例状态。

## 2. 生命周期、持久化与故障恢复

后端接口拟为 capabilities、prepare、observe、start、stop、reset、recover；所有写操作接收OperationContext与不可变计划。observe返回身份verified/unknown/mismatch和资源实际状态。未知或不匹配时禁止终止、删除、覆盖；返回人工核验入口。公开错误用稳定代码，详细私有日志留在独立状态根。

持久布局：实例元数据与操作账本、generations/<n>/节点磁盘及NVRAM、网络资源账本、有限额事件和证据目录。基盘以哈希定位只读；课程答案单独存储。账本引用运行时版本，升级不能删除活跃版本。

启动：持有实例操作锁 → 核验主体/代次/哈希/空间 → 写入意图 → 分配并登记资源 → 按DAG启动 → 实测身份及服务 → 提交结果。每个外部副作用前记意图、之后记资源身份；崩溃恢复先observe，不盲目重放。启动中部分失败只回收本次已确认归属的临时资源，运行节点保留并呈现部分失败。

停止：逆DAG请求正常关机，逐节点记录应答与实际退出；超时保留实例，强制结束作为单独明确操作。关闭GUI不停止实验；协调器持久存在。停止服务不能只靠PID，需创建时间、映像、所属实例及句柄核验。

重置：仅全部确认停止时允许；先检查空间/引用，准备完整新代次磁盘、NVRAM、网络计划，全部校验后原子切换活动代次。提交点之前取消则保留旧代次；之后返回新代次且不得伪称取消。跨文件与数据库不假设原子事务：采用准备清单、提交标记和可幂等恢复步骤。任何中断须能确定旧代次或新代次，无法确定时进入unknown并留现场。

回收：先生成对象/大小/引用/摘要的预览，执行前再次锁定并核对引用；运行中、证据封存、失败现场和旧代次恢复引用一律保留。删除失败逐对象登记，可重试，不把半完成当成功。空间预算计入新旧代次并存、临时下载、日志上限和安全余量；实际分配失败仍须恢复。

## 3. 43项任务的具体落地与验证

下表的接口和文件是设计目标；只有执行台账明确记录的切片已经实现。每行负测与原任务完成判据共同构成验收条件。

| ID | 设计交付与行为 | 必须验证的失败/边界 |
|---|---|---|
| A01 | 平台依赖登记到锁/进程/存储/网络/显示能力，能力缺失明确拒绝 | 未知平台与缺依赖不创建状态 |
| A02 | 不可变ExecutionPlan绑定宿主、客体、加速器和运行时摘要 | Mac参数等价，Windows不静默回退TCG |
| A03 | 统一契约、可信主体、CAS、持久事件与后端接口 | 跨主体、过期代次、重复提交、提交点取消、事件断档 |
| W01 | 固定构建完整清单；受保护控制、SDL首版显示、监督原型 | 非授权主体连接、控制重连、监督异常、冷启动/正常关机 |
| W02 | 普通用户监督进程、原生锁/ACL/进程句柄、端口归属账本 | PID复用、监督崩溃、ACL失败、端口被抢、不误杀外部进程 |
| W03 | CLI通过契约调用受限C01两节点执行器，运行时随包隔离 | 中文/空格路径、离线、双节点部分失败和保存继续 |
| W04 | 节点列表、课程导入、进度取消、重连与拓扑薄壳 | 重复点击、事件断档、关窗口后继续、错误恢复入口 |
| W05 | 安装版本与数据分离，迁移前备份，手动更新原子切换 | 离线依赖、迁移失败回退、签名异常、卸载保留数据 |
| W06 | 设备矩阵与最终包课程脚本，记录用户介入 | DPI/VPN/睡眠/磁盘不足/连续3轮重置；至少5名非开发者 |
| S01 | 严格v2解析、确定性DAG与资源计划 | 环路、重复地址、未知字段、计划摘要变化 |
| S02 | 包版本与场景版本分离；精确架构/能力变体选择 | 多匹配要求选择、不兼容拒绝、旧包原样保留 |
| S03 | 通用协调器按第2节执行整课停止/重置/恢复 | 每个副作用前后中断、两个实例隔离、磁盘与NVRAM一致 |
| S04 | 显式路由/DNS/时间模板；方向、协议、端口规则 | 应通与禁通、IPv6、默认出口、重置后规则恢复 |
| T01 | 拓扑读取计划及带时间的实测覆盖层 | 过期观测标记，不把设计IP显示成已获地址 |
| T02 | 编辑草稿→校验→差异预览→新代次；导出规范清单 | 图与清单语义往返、非法连接、运行场景不热修改 |
| P01 | 目录含来源、许可、架构、资源、准备路径与验证声明 | 缺资产、越界路径、错误摘要、验证声明不能冒充实测 |
| P02 | 单HTTPS源、签名索引、内容寻址缓存、partial下载 | 篡改/过期/回滚索引、源变更、中断续传与空间耗尽 |

| P04 | 校内只读镜像只改变位置，不改变资产身份 | 未授权再分发拒绝、教师答案不进入学生索引 |
| D01 | 专用Linux VM内Docker；只接受受限OCI声明与digest | 拒绝特权、宿主命名空间、socket及任意挂载 |

| E03 | 外部域节点恢复点与内部代次联合检查清单 | 单方恢复阻止整体ready；新认证、域服务与恢复一致性 |
| R03 | 服务端owner授权、教师/学生/管理员角色、每人实例配额 | 跨用户查询/操作拒绝、资源耗尽和审计不泄露凭据 |
| R04 | 课程指定前缀的数据通道，明确与控制隧道分离 | 禁默认路由/LAN桥接，断线清理仅限本次归属资源 |
| C01 | Linux工具+Web目标完整样板，教师与学生材料分离 | 安装→准备→业务任务→保存继续→整课重置，全程记录介入 |
| C02 | Windows合法来源配方，锁定固件/驱动及基线 | 桌面登录、服务、重启、日志和重置，不能只看启动窗口 |

| O02 | 隔离离线分析VM/容器，锁定工具与规则摘要 | 畸形输入、资源上限、禁网、相同证据可复现输出 |

## 4. Windows控制、显示与监督决策

首版显示选择独立SDL窗口，管理端提供打开/状态/重连入口；不承诺内嵌桌面或SPICE可用。受保护控制候选为私有命名管道或监督器持有的匿名管道代理；不得仅因帮助列表存在就认定QEMU支持所需传输。先用锁定构建做探针，验证端点ACL、客户端身份、重连与退出；若不满足，保留原型，不降级为无认证TCP。

监督器独立于GUI；GUI退出保持实验。Windows Job与监督器异常策略必须通过原生探针定案：默认不采用“监督器异常即杀全部子进程”的数据丢失策略；新监督器核验现有进程身份与端点后才恢复控制。无法可靠重新归属时标unknown，要求手动处理自有实验。端口分配不得“探测空闲→释放→启动”后假称已保留；需后端可继承句柄或启动握手核实实际监听归属，抢占失败撤销本次资源。

运行时清单锁定QEMU、DLL、固件、Python、显示依赖、来源及许可证。当前回传仅QEMU单文件及帮助查询；Smoke无网络启动是前置实验，不覆盖网络/控制恢复/G0。设备版本、完整清单与真实探针结果是验证输入，设计文档不得填造。

## 5. 网络、内容与远程信任边界

默认仅实验网络；多网卡节点不自动转发。规则包含源/目的网段、方向、协议端口、IPv4/IPv6和允许理由。每条allow配置有应通检查，每条边界有禁通检查，覆盖宿主、管理端、真实LAN和外网。外部VM自带出口不能由CTFLab窄隧道保证隔离，界面分别显示“已连接”和“隔离已验证”。添加出口是显式方案变更，非导入课程的附带动作。

签名索引使用固定信任根与可审计轮换，签名、有效期、递增版本和资产摘要均校验；具体算法/库在实现选型时核验一手文档并锁版本。未知密钥拒绝，离线使用已校验缓存；过期索引禁止取得新内容，不抹掉已安装课程。摘要用于身份，签名用于发布者信任，许可为独立分发门槛。

远程先一台自有Linux，SSH主机密钥固定；控制只接受白名单协议，文件同步限制到实例资产根。远端执行持续于连接之外，断线后按操作ID查询，禁止重复创建。多人是独立后续服务端授权层，不能把当前本机actor机制直接暴露到网络。

## 6. 验证顺序、证据与退出条件

1. V0设计复核：43项无遗漏，接口责任、依赖、失败恢复与验收对应；本地链接和文档回归通过。仅关闭设计范围。
2. V1本地基础：契约、平台策略、v2计划、目录、诊断、Windows驱动的单元/合成测试。按测试日志登记跳过，不操作现有VM。
3. V2 Windows G0：补完整构建/设备清单，Smoke启动回传，然后完成受保护控制/显示、监督、端口、正常关机、故障恢复。每个结果绑定独立状态根、派生盘和真实进程身份。
4. V3产品集成：实现并验证P03本地/S03与受限C01、W03—W05；最终安装包独立验收，Mac兼容路径另验。
5. V4 Windows G1：W06/C01/U01—U04联合，设备/用户/签名标准沿用Windows专项第6节，未完成则不公开宣称支持。
6. V5扩展：S04/C03 → D01—D03、E01→E02→E03；L01→R01→R02→R03→R04；C02/C04与O01/O02/C05/C06/C07按任务表各自前置推进。C05配方与证据设计可提前，真实课程必须单独通过。

测试记录含：任务ID、代码/运行时/资产摘要、宿主信息、实例/代次、命令、状态根、预期/实际、原盘前后摘要、失败/跳过、结束现场与恢复入口。注入点至少覆盖副作用前、执行中、完成未提交和提交后；网络至少覆盖应通/禁通；回收至少覆盖新增引用竞态。无实际实现的任务标“设计完成、待实现/验证”，不能用文档测试关闭。

## 7. 尚需验证输入与设计变更规则

硬件具体组合、Windows完整运行时、合法Windows/AD镜像、签名证书、反馈责任人与真实用户安排仍需实际输入；它们不阻止本基线设计，但阻止相应运行或发布门槛。不得编造当前支持版本。实施时若平台能力与本设计冲突，记录探针、变更影响和替代方案；接口/安全边界变动须更新任务表及验收矩阵。独立阶段完成前不把全43项执行状态改为完成。
