## 状态与范围

不能据“进程存活”保证来宾健康，也不能用重新打开客户端替代睡眠唤醒。

当前解决切片是**主动避免进入未验证的睡眠路径**，不是实现 ARM 挂起/唤醒。

默认不安装、不修改基盘；不更改锁屏、密码、屏保时限、网络、关机或电源按钮。
未接入无人值守安装或 GUI 自动执行，防护后的真实来宾验收尚待完成。

## 防护机制与依据

systemd 240 起提供 `AllowSuspend`、`AllowHibernation`、`AllowHybridSleep`、
`AllowSuspendThenHibernate`，可在 `[Sleep]` 段关闭对应模式。
依据：[systemd 官方手册源码](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd-sleep.conf.xml)。

工具在 `/etc/systemd/sleep.conf.d/90-ctflab-no-sleep.conf` 写入四个 `no`。
只接受 Linux ARM64，并要求 systemd 至少 240；不会在 Mac 或 x86 靶机上写入。
应用与撤销需 root 且必须传 `--confirm`。不通过重启 logind、重启来宾、
`systemctl mask` 或删除用户其他配置实现限制。

## 独立测试来宾中的操作

先把工具复制到**已授权的派生测试 Kali**，例如 `/tmp/ctflab-power-policy.py`。
不要直接在生产 Kali 或原始镜像里试验。登录和 sudo 口令由用户手动输入，
不提取安装凭据，也不临时开启剪贴板/文件传输通道。

以下命令全部在 Kali 终端执行，不是在 Mac 终端执行：

```sh
python3 /tmp/ctflab-power-policy.py status
sudo python3 /tmp/ctflab-power-policy.py apply --confirm
python3 /tmp/ctflab-power-policy.py status
```

需要核验 `sleep_block_verified=true`：自有文件完整，logind 的四项能力查询
均为 `no` 或 `na`。`unknown`、`yes` 或 `challenge` 不算通过。
应用后未证明生效时返回 2，保留可撤销配置并报告实际能力，不冒充成功。
后续还必须验证桌面睡眠入口被禁用或明确拒绝，锁屏/手动解锁、显示恢复、
正常关机和重启均正常。系统配置可能被其他 drop-in 覆盖，不能只看文件。

## 撤销

```sh
sudo python3 /tmp/ctflab-power-policy.py restore --confirm
python3 /tmp/ctflab-power-policy.py status
```

撤销只删除字节与本工具完全一致的自有文件，不删除父目录，不更改其他
drop-in；文件被用户修改或为符号链接时拒绝操作，交给人工复核。
撤销不保证虚拟硬件可以睡眠或恢复，只撤销本工具的限制。

### Dock 回调与装饰切换的源码复核

Dock 点不开提供了明确的实现缺口，但不能外推为所有历史故障的唯一原因。

修正仅在 macOS 开启原生应用生命周期，并仅向已知
GtkApplicationQuartzDelegate 添加缺失的 reopen 方法，再进入现有
activate/去最小化路径。不替换代理、不覆盖已有方法、不接触来宾认证。
原生回调专项使用独立测试类验证首次添加、再次添加拒绝、既有实现
不变及空代理拒绝；客户端专项现为 28 项通过。

[Quartz 装饰实现](https://github.com/GNOME/gtk/blob/3.24.52/gdk/quartz/gdkwindow-quartz.c)
在切换标题栏时直接改变 NSWindow。全屏切换候选补充一次 GDK 内容尺寸
请求，绕过 GtkWindow 的旧请求缓存，再由实际 size-allocate 驱动来宾
分辨率；不写死来宾坐标，不将请求尺寸冒充实际尺寸。待真实切换日志
与画面同时证明，保持候选状态。
